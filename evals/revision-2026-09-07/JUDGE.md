# Задание модельному рецензенту

Оцени приложенные тройки русскоязычных текстов X/Y/Z. Ты не знаешь, как они
получены. Не угадывай происхождение, не оценивай человеческое авторство.
Все исходники синтетические; проверяй по ним. Не используй инструменты,
другие файлы или веб-поиск. Не переписывай ответы.

Сначала проверь факты и разрешения. `public` допускает использование с нужной
атрибуцией; `paraphrase_only` — пересказ, не прямую цитату; `private` запрещает
публикацию содержания, включая пересказ. Регистр не оправдывает выдумку,
причинное усиление, изменённые числа или неподтверждённую биографию. Но новая
формулировка не становится выдумкой из-за несовпадения слов: разумный пересказ,
очевидная арифметика, метафора и выраженная автором позиция допустимы.
Различай стилистический оборот и утверждение о событии. Оцени существенность:
не всякая неточная связка критична. Одна найденная ошибка не доказывает,
что другой текст точен — каждый проверяется по исходникам.

Далее оцени выполнение запроса и качество чтения: понятную мысль, естественный
язык, соответствие тону, движение без пустых повторов, штампов и лишних оговорок.
Короткое не обязательно лучше длинного. Тире, списки, противопоставления не
ошибки сами по себе. Рассказ не обязан открываться выводом, личный пост — давать
совет; анонсу важнее условия участия. Сохранение значимого авторского замысла
или позиции важно; перечислять все исходные детали не требуется.

Объём уже измерен внешним одинаковым счётчиком, включая весь ответ. Notes
помогают понять исходники, но не задают единственную композицию или стиль.

Статусы:

- `pass`: существенных дефектов в проверке не найдено, не гарантия качества.
- `revision`: нужен конкретный исправимый редакторский шаг или нарушено
  требование задания, включая объём; критической ошибки нет.
- `critical`: конкретная выдумка, существенное искажение источника, нарушение
  цитирования/приватности или неподдержанное обвинение.

Для каждой существенной находки нужны точная цитата из ответа, источник
(или null), причина и минимальная правка. При пропущенной мысли цитируй место,
где возникает потеря, и явно объясни пропуск, а не придумывай отсутствующую
цитату. Для длины достаточно цитаты начала и измерения из пакета. Для pass
обычно нет findings. Не называй собственный любимый стиль единственно верным.

Дай два отдельных ранжирования каждой тройки, от лучшего к худшему:

- `editorial_ranking`: только качество чтения с учётом формы и голоса.
- `practical_ranking`: сначала критические ошибки, затем выполнение запроса,
  потом редактура. Красота не компенсирует существенную выдумку.

Ранжирование — массив групп меток. Ничья — метки в одной группе. Примеры
структуры: `[["X"],["Y","Z"]]` или `[["X","Y","Z"]]`. Все X/Y/Z ровно один
раз, пустых групп нет. Не выбирай победителя любой ценой. Обоснуй оба порядка
конкретными свойствами текстов. Отвечай по всем полученным тройкам и только им.

Верни только JSON без markdown-ограждения:

```json
{
  "reviews": [
    {
      "trio_id": "из пакета",
      "X": {
        "status": "revision",
        "findings": [{
          "severity": "revision",
          "category": "facts",
          "quote": "точная фраза",
          "source_id": "S1",
          "reason": "почему это дефект",
          "minimal_fix": "минимальная правка"
        }]
      },
      "Y": {"status": "pass", "findings": []},
      "Z": {"status": "pass", "findings": []},
      "editorial_ranking": [["X", "Y", "Z"]],
      "editorial_reason": "конкретное сравнение",
      "practical_ranking": [["Y", "Z"], ["X"]],
      "practical_reason": "конкретное сравнение"
    }
  ],
  "limits": "Модельная оценка: возможны пропуски и ложные замечания."
}
```

Допустимые severity: `revision`, `critical`; category: `facts`, `permissions`,
`brief`, `style`; source_id: строка или null. Пример выше показывает формат,
не оценивает приложенные тексты.
