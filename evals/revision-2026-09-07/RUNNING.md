# Как воспроизвести трёхстороннюю проверку

Все команды — из корня репозитория. Нужны Python 3.10+ и уже авторизованный
Codex CLI. На фактическом запуске: `codex-cli 0.153.4`. Код runner использует
только стандартную библиотеку; не устанавливает зависимости и не копирует ключи.
Это инструмент разработки, не часть устанавливаемого навыка.

Модельные вызовы расходуют доступный лимит/бюджет хоста. `prepare`, `blind`,
`judge-prepare`, `export` и тесты работают без них. Только явно указанный
`--execute` запускает модели: до 36 авторских вызовов и 4 рецензий.

Используйте новые каталоги каждого эксперимента. Команды не перезаписывают
существующие снимки и экспорт. `.local/` исключён из Git; сырые логи туда
сохраняются для проверки, но не публикуются.

```bash
python3 tools/run_revision.py prepare \
  --dest .local/revision-2026-09-07-writers \
  --dataset evals/revision-2026-09-07/cases.json \
  --protocol evals/revision-2026-09-07/PROTOCOL.md \
  --rubric evals/revision-2026-09-07/JUDGE.md

python3 tools/run_revision.py run \
  --run-dir .local/revision-2026-09-07-writers --execute

python3 tools/run_revision.py blind \
  --run-dir .local/revision-2026-09-07-writers \
  --dest .local/revision-2026-09-07-blind

python3 tools/run_revision.py judge-prepare \
  --packet .local/revision-2026-09-07-blind/packet.json \
  --rubric evals/revision-2026-09-07/JUDGE.md \
  --dest .local/revision-2026-09-07-judges

python3 tools/run_revision.py judge-run \
  --dest .local/revision-2026-09-07-judges --execute

python3 tools/run_revision.py export \
  --run-dir .local/revision-2026-09-07-writers \
  --judges-dir .local/revision-2026-09-07-judges \
  --dest evals/revision-2026-09-07/results
```

`prepare` берёт candidate из текущих пяти документов навыка, previous — из
сохранённых снимков первого A/B. Для повторения именно исторического сравнения
используйте соответствующую версию Git либо восстановите candidate в отдельном
рабочем checkout из точного экспортированного снимка. Не подменяйте навык в
работающем агенте. Старые задания теперь известны: повторение проверяет
воспроизводимость процедуры, но уже не является новой отложенной выборкой.

При перезапуске завершённые и неудачные записи не вызывают модель повторно.
Если процесс оборвался после создания `attempts/`, но до terminal record,
runner останавливается: это защита от незаметного повторения. Не удаляйте marker
для получения нового ответа; исследуйте исходную попытку и сохраните её статус.
Ненулевой exit code может означать записанный сбой — проверьте результаты,
не перезапускайте весь эксперимент ради «зелёного» вывода.

Экспорт проверяет хеши, точные ответы, исходные события CLI, соответствие
заданий/меток и неизменность рубрики. Публикуются только разрешённые поля;
сырые логи, системные пути и данные авторизации не включаются. Проверка по
шаблонам не доказывает отсутствие всех секретов: нужен просмотр материалов.
Нормализованные rankings отменяют перестановку меток второго рецензента;
исходные отзывы сохранены отдельно, включая их исходные X/Y/Z.

```bash
python3 -m unittest discover -s tests -p 'test_run_revision.py' -v
python3 -m unittest discover -s tests -v
python3 tools/validate_package.py
```

Тесты runner используют поддельный локальный CLI/ответы и не расходуют модельный
бюджет. Они проверяют процедуру, не литературное качество.

`CHECKER.json` — отдельная post-hoc диагностика реальных ответов вызовом
`editorial_check.analyze`: исходный текст, пакет `version: 1` с источниками
соответствующего кейса, его `min_words`/`max_words`, без профиля голоса.
Источник для API хешируется как canonical JSON, а текст — по точным UTF-8
байтам. В тестах есть повторное вычисление этих записей после наличия экспорта.
Эти результаты не показывались авторам или рецензентам и не меняли их ответы.
