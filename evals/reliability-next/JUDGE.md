# Модельная оценка точности двух текстов

Оцени пары X/Y по приложенным запросу и синтетическим источникам. Не угадывай,
как тексты получены. Не используй инструменты, другие материалы или веб-поиск.
Оба варианта могут быть корректными либо ошибочными; одинаковый текст получает
одинаковую оценку. Не ищи отличие или победителя любой ценой.

Сначала независимо сверь каждый текст с источниками. Проверяй смысл, а не
совпадение слов: разумный пересказ и арифметика допустимы. Метафору не читай
как буквальное событие. Для существенной подмены установи, какие сведения
читатель извлечёт из фразы и почему исходники их не поддерживают. Сохраняй
значение времени, условий, количества, причинности, уверенности, отрицания,
свидетельства и позиции автора. Не требуй включить все второстепенные детали.

`public` разрешает использование с нужной атрибуцией; `paraphrase_only` — только
пересказ без прямых цитат; `private` запрещает использование содержания в
публичном тексте, включая пересказ. Разрешение не удостоверяет истинность.
Нельзя приписывать источникам новые слова, опыт или мотив. Исправление не должно
стирать главную мысль или нужную оговорку. Стилевой вкус не определяет точность.

Статусы: `pass` — существенных дефектов по этому заданию не найдено;
`revision` — нужна конкретная некритическая правка, включая нарушение объёма;
`critical` — существенная неподдержанная фактическая посылка, искажение смысла,
нарушение прав/цитирования или выдуманный опыт. Не всякая шероховатость критична.
Статус соответствует самому серьёзному обоснованному замечанию.

Каждая находка требует дословной цитаты именно из ответа, source_id или null,
объяснения с относящимся исходным фрагментом и минимальной правки. Для отсутствия
важной мысли цитируй реальное место, где возникла потеря, а не выдуманную строку.
Не считай общую фразу о возможной проверке утверждением, что проверка проведена.

`practical_preference`: сначала подтверждённые существенные ошибки и права,
затем сохранение главной мысли и выполнение задания. При сопоставимой пригодности
ставь `tie`; более приятный ритм не разрывает эту ничью. Количество сохранённых
малозначительных фактов само по себе не делает текст надёжнее.

`editorial_preference`: отдельно сравни понятность, естественность, голос и
уместность формы, не переносить сюда фактический статус. Можно предпочесть
чтение ошибочного текста, но это не улучшает его практическую оценку.
Объём уже измерен одинаковым счётчиком; ничья допустима в обоих измерениях.

Верни только JSON следующей структуры (пример показывает форму, не вердикт):

```json
{
  "reviews": [
    {
      "pair_id": "из пакета",
      "X": {
        "status": "revision",
        "findings": [{
          "severity": "revision",
          "category": "facts",
          "quote": "дословный фрагмент ответа",
          "source_id": "id источника или null",
          "reason": "что говорит исходник и почему текст меняет смысл",
          "minimal_fix": "минимальная исправляющая правка"
        }]
      },
      "Y": {"status": "pass", "findings": []},
      "editorial_preference": "tie",
      "editorial_reason": "сравнение только подачи",
      "practical_preference": "Y",
      "practical_reason": "сравнение точности и выполнения запроса"
    }
  ],
  "limits": "Модельная оценка по предоставленным источникам; возможны пропуски и ложные замечания."
}
```

Допустимые category: `facts`, `permissions`, `brief`, `style`; severity:
`revision`, `critical`; source_id — строка или настоящее JSON null. Preference:
`X`, `Y`, `tie`. Верни все полученные пары ровно по одному разу.
