# Задание независимому модельному рецензенту

Оцени приложенные пары русскоязычных текстов. Ты не знаешь, как получены X и Y.
Не пытайся угадать вариант или происхождение, не оценивай авторство человека.
Все исходники синтетические; проверяй соответствие именно им, без веб-поиска.
Не используй инструменты и не переписывай тексты. Не читай другие файлы.

Сначала проверь факты и разрешённость использования. У public допустимо
публичное использование, paraphrase_only допускает пересказ без прямой цитаты,
private запрещает публичное использование содержания, включая пересказ.
Регистр и яркость не оправдывают выдумку, причинное усиление, неподтверждённую
биографию или изменённые цифры. В то же время не называй новую формулировку
выдумкой только потому, что она не совпадает дословно с исходником. Разумный
пересказ и очевидный арифметический вывод допустимы. Различай субъективную
оценку/метафору и утверждение о событии. Не превращай всякую неточную связку
в критическую ошибку: оцени, изменяет ли она существенный смысл.

Затем проверь выполнение запроса и редактуру: ранний полезный ответ,
естественный русский язык, соответствие голосу, движение абзацев без повторов,
канцелярита, клише и лишних оговорок. Короткое не обязательно лучше длинного.
Тире, списки и противопоставления не являются ошибками сами по себе.
Критерии зависят от жанра: рассказ не обязан открываться выводом, личный пост
не обязан давать совет; анонсу важнее понятные условия участия. Не навязывай
всем текстам одну композицию.
Диапазон слов проверен одним внешним счётчиком, включает весь ответ.

Статусы для каждого текста:

- pass: существенных дефектов в данной проверке не найдено; это не гарантия.
- revision: нужен конкретный исправимый редакторский шаг или нарушено условие
  задания, включая объём; нет критической ошибки.
- critical: есть конкретная выдумка, существенное искажение источника,
  нарушение цитирования/приватности либо неподдержанное обвинение.

Для каждой находки укажи точную цитату ответа, source_id (или null при отсутствии
опоры), объяснение и минимальную правку. Цитата должна реально быть в ответе.
Не требуй включения всех исходных деталей, если они не нужны задаче. Не считай
заранее выбранный идеальный стиль единственно правильным. Reviewer_notes —
помощь для проверки исходников, а не обязательная композиция ответа.

По каждой паре дай два отдельных предпочтения: editorial_preference — только
качество чтения с учётом заданного голоса; practical_preference — пригодность
результата, где сначала учитываются критические ошибки, затем выполнение
задания, потом редактура. Допустимые значения X, Y, tie. Не ищи победителя любой
ценой. Для обоих предпочтений нужно предметное основание.

Верни только JSON без markdown-ограждения:

```json
{
  "reviews": [
    {
      "pair_id": "из пакета",
      "X": {
        "status": "pass",
        "findings": [
          {
            "severity": "revision",
            "category": "facts|permissions|brief|style",
            "quote": "точная фраза",
            "source_id": "S1",
            "reason": "почему это дефект",
            "minimal_fix": "минимальная правка"
          }
        ]
      },
      "Y": {"status": "pass", "findings": []},
      "editorial_preference": "tie",
      "editorial_reason": "сравнение конкретных свойств",
      "practical_preference": "tie",
      "practical_reason": "сравнение конкретных свойств"
    }
  ],
  "limits": "Оценка модельная; возможны пропуски и ложные замечания."
}
```

Пример структуры не является оценкой приложенных текстов: при pass обычно нет
существенных findings. Для нарушения длины достаточно цитаты начала ответа и
точных измерений из пакета. Отвечай по всем полученным парам и только по ним.
