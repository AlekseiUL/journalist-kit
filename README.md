# Journalist Kit

Source-first редактура, журналистика и авторский голос — для агента, который у вас уже есть.

[English](README.en.md) · [Быстрый полезный маршрут](docs/golden-path.md) · [Пример редактуры](examples/library-hours/README.md) · [Установка](docs/integrations.md) · [Как проверяем качество](docs/evaluation.md)

**Новая проверка шести форм:** на 24 новых текстах устойчивый выигрыш beta.3
перед обычным автором не подтверждён; есть смысловые подмены. Подготовлен слепой
читательский пакет, человеческих оценок пока нет.
[Результаты и ограничения](evals/product-six-forms-2026-09-07/README.md).
Отдельный редактор Astra исправил 6/6 известных дефектов, но этот проход
не внедрён и не проверялся вместе с модулем на новых заданиях.
[Редакторская регрессия](evals/editor-astra-2026-09-07/README.md).

**Beta.3: проще, без обещания безошибочности.** Инструкции сокращены примерно
на четверть. В проверке 36 новых текстов оба модельных рецензента чаще предпочитали
её обычному автору. Но преимущество надёжности перед beta.1 не подтвердилось:
оба отметили у beta.3 больше критических ошибок. Это **экспериментальная beta**,
не безусловно рекомендуемый апгрейд. [Все результаты и тексты](evals/reliability-2026-09-07/README.md).
[Первое A/B beta.1](evals/ab-2026-09-07/README.md) и
[опыт beta.2](evals/revision-2026-09-07/README.md) сохранены отдельно.

**Beta.** Даёт агенту правила работы по источникам, сохранения голоса и редактуры
штампов на уровне мысли и композиции. Не доказывает человеческое авторство,
не заменяет репортёра и не обещает тексты без редакторских ошибок.

**Следующий кандидат — editor-first.** При наличии черновика он сначала фиксирует
субъект, действие, время, условия, уверенность и позицию автора, затем делает
минимальную полезную правку и проверяет именно изменённые утверждения. Все
журналистские references больше не предполагается загружать в каждое задание.
Это направление ещё не прошло новый behavioral holdout и не меняет результатов
beta.3 ниже. [Заранее зафиксированный следующий gate](evals/next-source-first-holdout/PROTOCOL.md).

Закрытая beta в приватном репозитории `AlekseiUL/journalist-kit`.
Для `git clone` ниже нужны доступ к репозиторию и авторизация GitHub.
Публичный выпуск и лицензия на распространение пока не утверждены.

## Что подключается

Journalist Kit поставляет один навык с техническим именем `source-and-voice`.
Это имя используется в командах и каталогах установки.

- **Журналистская дисциплина:** что известно, на чём держится вывод, чего источник не подтверждает.
- **Редакторский проход:** пустые вступления, шаблонные противопоставления,
  повторные финалы, канцелярит и незаметное усиление исходной мысли.
- **Ваш голос:** регистр, ритм, собственные предпочтения — без обязательного чужого стиля.
- **Локальная диагностика:** объём, точные фрагменты для пересмотра, отдельные
  риски использования источников и хеш проверенного текста.

Один автор по умолчанию. Для короткого поста — короткий маршрут. Для статьи —
работа с источниками и подходящей формой. Специалист нужен ради конкретного
пробела или независимой проверки, а не ради количества агентов.

## Быстрый старт: Hermes

Нужны Git и Python 3.10+. Сервер, ключ API и установка Python-библиотек не нужны.
Сам текст пишет уже настроенная у вас модель.

```bash
git clone https://github.com/AlekseiUL/journalist-kit.git
cd journalist-kit
python3 tools/install.py --dest "$HOME/.hermes/skills"
python3 tools/install.py --dest "$HOME/.hermes/skills" --apply
```

Первая команда установки только показывает план. Вторая копирует **один новый
навык**. Существующий каталог не перезаписывается. Конфигурация, память, история
и другие агенты не меняются; перезапуска нет.

Для именованного профиля укажите именно его каталог `skills`:
[инструкция и проверка установки](docs/integrations.md). Начните новую сессию
Hermes и попросите:

```text
Используй source-and-voice. Напиши короткий пост по материалам ниже.
Сохрани мой спокойный разговорный тон. Не добавляй фактов и личных историй.
Вот материалы: ...
```

Другой skills-совместимый агент может использовать тот же каталог навыка.
Это переносимость файлов, **не заявление о проверенной работе во всех клиентах**.
Установка не создаёт веб-поиск и не заставляет хост исполнять Python.

## Сначала посмотрите на текст

В [демонстрации о режиме библиотеки](examples/library-hours/README.md) лежат
исходники, намеренно неудачный текст и отредактированный вариант. Видно, какие
слова были пустыми, где изменился смысл и почему хорошая редактура не требует
выдумывать историю.

Это специально составленный пример, **не результат слепого сравнения моделей**.

Для реальной работы начните с [короткого editor-first маршрута](docs/golden-path.md):
обычному посту достаточно черновика, цели и фактов; полный журналистский контур
и отдельный рецензент включаются только при соответствующем риске.

Локальную диагностику можно запустить прямо из репозитория:

```bash
python3 skills/source-and-voice/scripts/editorial_check.py \
  examples/library-hours/after.txt \
  --sources examples/library-hours/sources.json
```

## Не шесть одинаковых стилей

| Что выбираем | Варианты |
|---|---|
| Результат работы | Угол материала, план интервью, карта фактов и пробелов, объяснение по источникам, статья, план расследования |
| Форма | Новость, полезный разбор, интервью/профиль, репортажное повествование, анализ/колонка, журналистика решений |
| Голос | Тон текущего задания, ваш профиль подачи или ясный регистр по форме |

Формы не требуют сцены, морали или призыва к действию там, где они не нужны.
Обычный пост или редактура не обязаны становиться журналистским расследованием.

Отдельный профиль для начала не нужен. Достаточно в запросе указать, например:

- «Личный пост с лёгкой самоиронией. Вот мои заметки; нового опыта не добавляй».
- «Тёплое объявление: читатель должен сразу понять, что меняется и что делать».
- «Спокойно отредактируй колонку, сохрани мою позицию и удачные образы».

Передайте цель, исходники и желаемый объём. Голос — не обязанность шутить:
новость может оставаться собранной, а портрет — строиться на решениях героя.

## Антинейронщина без нового шаблона

Модуль предлагает редактировать конкретный дефект, а не запрещать нормальную
грамматику. Тире, список, слово «является» или честное противопоставление сами по
себе не делают текст плохим. Равная длина предложений не доказывает происхождение.

В одном проходе автор проверяет композицию, голос и язык, сохраняя работающую
мысль и интонацию. Живость прежде всего дают выбор деталей, порядок и ритм.
Если красивая фраза требует догадки, лучше оставить формулировку ближе к источнику
и улучшить текст вокруг неё. Затем автор сверяет смысл окончательных утверждений:
кто что сделал, откуда это известно, при каких условиях. Метафору не нужно читать
буквально, но она не должна сообщать о новом событии. «Я не заметил» не превращается
в «этого не было». Это редакторский приём, а не гарантия отсутствия ошибок.

В предыдущей проверке beta.2 на 36 текстах помощник не выдал стилевых сигналов
и пропустил ошибки смысла. Его нулевой exit code нельзя использовать как автоматический
пропуск к публикации. [Что именно он заметил и пропустил](evals/revision-2026-09-07/AUDIT.md).

Настройки голоса необязательны. Начните с
[нейтрального примера](skills/source-and-voice/assets/voice.example.json) и
[руководства](skills/source-and-voice/references/voice.md). Личные образцы
храните вне публичного репозитория.

## Что действительно проверено — и что нет

| Уровень | Что он означает |
|---|---|
| Код и установка | Unit/integration tests проверяют обработку входов, измерения, ограничения и переносимость пакета |
| Стилевые сигналы | Локальные эвристики указывают, что стоит перечитать; возможны пропуски и ложные срабатывания |
| Источники | Скрипт ловит отдельные структурные риски, но всегда сообщает `NOT_REVIEWED` для смысловой достоверности |
| Редакторская проверка | Агент или человек отдельно читает точный текст вместе с источниками; ограничения проверки сохраняются |
| Публикация | Требует разрешения и механизмов вашего хоста; пакет ничего не публикует |

Хеш связывает отчёт с конкретными байтами, но не удостоверяет истинность и не
заменяет контроль отправки в вашем агенте. Подробности —
[контракт диагностического скрипта](docs/checker.md).

Утверждение «лучше других навыков» пока **не установлено**. Для его проверки
есть [синтетический набор заданий](evals/README.md) и
[протокол сравнительной оценки](docs/evaluation.md). Результаты и ограничения
первой проверки пакета фиксируются в [отчёте выпуска](docs/release-check.md).

## Уже есть агент? Этого достаточно

Подключите только навык. Если хотите отдельного автора, используйте
[необязательную конфигурацию «Автор-редактор»](docs/author-agent.md) — она
ссылается на то же ядро, а не создаёт второй набор правил.

Нет MCP-сервера, очереди задач, автопостинга, платной подписки на проверяющий
сервис или привязки к одному провайдеру. Дополнительная модельная редактура
использует возможности и бюджет вашего хоста; она не является бесплатной
по определению.

## Разработка

```bash
python3 -m unittest discover -s tests -v
python3 tools/validate_package.py
git diff --check
```

CI проверяет код и комплектность, но не оценивает литературное качество.
Присылайте воспроизводимый пример: исходные материалы, запрос, результат,
модель и конкретный дефект. Удалите личные данные и закрытые источники.
См. [CONTRIBUTING.md](CONTRIBUTING.md).
